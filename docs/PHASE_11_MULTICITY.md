# Phase 11：多城市与多方案基础

## 本阶段目标

把 TripWeaver 从京沪专用纵向切片扩展为可泛化的 10 城市规划基础，同时为后续连续对话和局部重规划建立不会推翻 Planner 的领域接口。

## 多城市 Fixture

每个城市包含 6 个景点种子和 2 个住宿区域。交通时长与价格根据城市中心距离按固定公式生成。所有结果继续标记为 `FIXTURE` 或 `ESTIMATED`，只用于无网络演示、回归测试和实时数据降级。

北京—上海的旧交通 ID 被保留，以保证已有铁路与航空 Snapshot 合同测试继续成立。

## 多目标方案

`AlternativeTripPlanningService` 在同一个 `PlanningCatalog` 上分别运行：

- `BUDGET`：价格权重最高
- `BALANCED`：平衡价格、耗时与通勤
- `TIME`：交通与市内通勤时间权重最高

三种方案都独立通过 Validator，方案差异来自确定性目标函数，不由解释文本伪造。

## 局部重规划接口

`PlanningOverrides` 当前支持：

- 固定去程 ID
- 固定返程 ID
- 固定住宿 ID
- 住宿每晚上限
- 排除景点 ID

后续对话层只需把“返程不要飞机”“酒店控制在 500 元以内”“第二天博物馆换掉”等意图转换为 override，再复用冻结 Snapshot 重新运行受影响部分。
